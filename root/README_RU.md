# Arden Engine — расширенное описание

## Что это

**Arden Engine** — открытый R&D-проект на **Rust + Bevy** под архитектуру гибридного voxel / mesh движка.

Проект пока не является готовым игровым движком. Это экспериментальная кодовая база, где я постепенно собираю ядро, проверяю идеи в lab-сценах и фиксирую технические решения в документации.

---

Статус: **ранняя экспериментальная разработка**.

Текущий код можно запускать и проверять, но его нельзя считать стабильным API, редактором или production-ready движком.  
Часть решений временная, часть модулей будет переписываться, а часть старых MVP-следов пока сохранена как исторический контекст.

---

## Зачем проект существует

Arden нужен мне как практическая лаборатория для изучения архитектуры движков.  
Не только “прочитать как это устроено”, а собрать живой код, столкнуться с ошибками структуры, увидеть временные костыли и постепенно вытащить из этого рабочую систему.

Главный интерес проекта — гибридный мир: где voxel-данные, mesh-представление, spatial truth, debug-инструменты и будущие runtime-слои не существуют отдельно, а собираются в одну понятную архитектуру.

Документация здесь является частью разработки. Она нужна не для красивой витрины, а чтобы сохранять след: что уже работает, что сырое, почему решение появилось и что будет меняться дальше.

## Философия коротко

Arden не должен быть “чёрным ящиком”.

Основные принципы:

- **наблюдаемость** — внутренние состояния должны быть видимы;
- **модульность** — слой должен иметь понятную ответственность;
- **проверяемость** — архитектура должна подтверждаться в живой сцене;
- **честная фиксация состояния** — временные решения, сырой код и будущие переделки не прячутся, а документируются.

## Быстрый запуск

Из корня репозитория:

```bash
cargo run
```

Что можно потрогать сейчас

Текущая lab-сцена позволяет проверить:

* fly-камеру;
* debug HUD;
* machine / human notation;
* spatial probe;
* pinned target;
* layered gizmos;
* finite voxel sandbox;
* Paint / Erase;
* SelectBox;
* Fill / Delete volume;
* Clipboard copy/paste;
* save/load lab snapshot.

## Управление

### Камера

| Ввод | Действие |
|---|---|
| `W / A / S / D` | движение камеры |
| `Space` | вверх |
| `Left Ctrl` | вниз |
| `Shift` | ускорение |
| `Right Mouse` | поворот камеры |
| `Shift + Mouse Wheel` | движение камеры вперёд / назад |

### Debug / HUD

| Ввод | Действие |
|---|---|
| `F1` | включить / выключить HUD |
| `F2` | включить / выключить gizmos |
| `PageUp / PageDown` | переключить debug lens |
| `F3` | переключить machine / human notation |
| `F4` | переключить compact / detailed view |
| `Q` | закрепить текущую inspect-точку |
| `E` | очистить закреплённую точку |

### Lab Tools

| Ввод | Действие |
|---|---|
| `1` | Inspect |
| `2` | SelectBox |
| `3` | Paint |
| `4` | Erase |
| `Left Mouse` | применить текущий инструмент |
| `F` | заполнить выделенный объём |
| `Delete` | удалить выделенный объём |
| `C` | скопировать выделенный объём |
| `V` | вставить clipboard volume |
| `F5` | сохранить lab snapshot |
| `F9` | загрузить lab snapshot |

> Инструменты редактирования работают в **Edit mode**.  
> Переключение режима доступно через HUD.

## 🤝 Руководство по участию в проекте Arden Engine

Спасибо за интерес к **Arden Engine**!  
Ваше участие вдохновляет и вы можете внести вклад — через код, документацию, идеи или исследования.

---

### 🧭 **Принципы участия**

- Соблюдайте уважительный тон общения (см. [Code of Conduct](./CODE_OF_CONDUCT.md)).  
- Прежде чем начать крупное изменение — обсудите идею в **Issues** или через почту:  
  📧 **arden.engine@proton.me**
- Все изменения проходят через **Pull Request**, с кратким описанием цели и сути изменений.

---

### 🧩 **Формы участия**

Вы можете помочь проекту, если:
- исправляете ошибки или улучшаете код (`/src`);  
- редактируете документацию (`/docs`); 
- дополняете концепт; 
- предлагаете идеи для архитектуры;  
- тестируете производительность или собираете отчёты о багах;  
- создаёте визуальные материалы, схемы или концепт-документы.

#### 🧱 **Как оформить Pull Request**

Если вы вносили идеи, тестировали функции, улучшали документацию,  
создавали модули или помогали в исследованиях —  
можно открыть **pull request** и добавить себя в список.  

Каждый вклад — технический, художественный или концептуальный —  
будет отмечен в репозитории.

Для участия и добавления информации о себе:

 1. Сделайте **fork** репозитория на GitHub.  
 2. Добавьте своё имя и роль в таблицу выше.  
 3. Создайте **pull request** — я проверю и внесу изменения в основную ветку.
